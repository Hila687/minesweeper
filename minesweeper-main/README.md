# שולה המוקשים ב־TypeScript

בתרגיל הזה תממשי משחק שולה המוקשים שפועל בדפדפן. הלוח מחולק למשבצות, ובחלק מהן מוסתרים מוקשים. בתחילת המשחק כל המשבצות סגורות. עלייך לזהות את המוקשים, לסמן אותם בדגלים ולפתוח את המשבצות הבטוחות בלי ללחוץ על מוקש.

את המשחק יש לממש ב־TypeScript עם HTML ו־CSS, ללא React. בריפוסיטורי מצורפים קובצי ההגדרות הדרושים להרצה וקובץ כניסה ראשוני. מימוש המשחק עצמו הוא חלק מהתרגיל.

## הנחיות עבודה

העבודה עצמאית. ניתן להיעזר במקורות שניתנו, במצגות ובאינטרנט, ללא כלי AI.

## פתיחת הפרויקט

1. בצעי CLONE לריפוסיטורי שהוקצה לך.
2. פתחי ב־VS Code את התיקייה המכילה את `package.json`.
3. עברי לבראנץ׳ העבודה שלך.
4. ודאי שמותקנת סביבת Node.js מתאימה. לפרויקט נדרשת גרסה 22.12 ומעלה. אם נדרשת התקנה, השתמשי בגרסת LTS עדכנית.
5. התקיני את חבילות הפרויקט:

```bash
npm ci
```

6. הפעילי את סביבת הפיתוח:

```bash
npm run dev
```

פתחי בדפדפן את הכתובת שמופיעה ליד `Local` בטרמינל. השאירי את הטרמינל פועל בזמן העבודה. אין צורך ליצור פרויקט חדש בתוך הריפוסיטורי.

אם PowerShell חוסם את `npm.ps1`, אפשר להשתמש בטרמינל מסוג Command Prompt. אם הורדת החבילות נחסמת ברשת הקורס, פני לסגל עם הפקודה שהרצת והודעת השגיאה המלאה.

## חלק א הלוח ונתוני המשחק

1. צרי לוח ברירת מחדל בגודל 9 על 9, כלומר 81 משבצות.
2. פזרי בלוח 10 מוקשים באופן אקראי. אין להציב יותר ממוקש אחד באותה משבצת.
3. בתחילת כל משחק כל המשבצות יהיו סגורות, כך שלא ניתן יהיה לזהות אילו משבצות מכילות מוקשים.
4. לכל משבצת הגדירי את המידע הנדרש כדי לדעת אם יש בה מוקש, אם היא פתוחה, אם היא מסומנת בדגל וכמה מוקשים נמצאים סביבה.
5. בחישוב השכנות יש לכלול את המשבצות שנוגעות במשבצת בצדדים ובאלכסונים. למשבצת פנימית יש עד שמונה שכנות. בפינות ובקצוות יש פחות שכנות ואין לחרוג מגבולות הלוח.
6. תציגי טיימר המתחיל ספירה כאשר מתחיל המשחק, עצרי אותו כאשר נגמר המשחק


## חלק ב פתיחת משבצות

לחיצה שמאלית על משבצת סגורה שאינה מסומנת בדגל תפתח אותה.

- אם יש במשבצת מוקש, המשחק מסתיים בהפסד. חשפי את כל המוקשים והציגי הודעה מתאימה.
- אם אין במשבצת מוקש, הציגי את מספר המוקשים שנמצאים במשבצות השכנות לה.
- אם מספר המוקשים מסביב הוא 0, פתחי באופן רקורסיבי את השכנות הבטוחות שלה. המשיכי לפתוח אזורים ללא מוקשים עד שמגיעים למשבצות שמספרן גדול מ־0. משבצות המספרים שבגבול האזור ייפתחו גם הן, אך לא ימשיכו את הפתיחה הרקורסיבית.
- משבצת שכבר נפתחה לא תיפתח שוב. פתיחה רקורסיבית לא תפתח מוקש או משבצת שמסומנת בדגל.


## חלק ג סימון בדגלים

לחיצה ימנית על משבצת סגורה תחליף בין שני מצבים:

- משבצת שאינה מסומנת תקבל סימון של דגל.
- משבצת מסומנת תאבד את הדגל ותחזור להיות ללא סימון.

אין לסמן משבצת שכבר נפתחה. אין לפתוח בלחיצה שמאלית משבצת מסומנת; כדי לפתוח אותה יש להסיר תחילה את הדגל.

בעת לחיצה ימנית על משבצת בלוח, מנעי את פתיחת תפריט ההקשר הרגיל של הדפדפן. הוסיפי לממשק מונה דגלים, ועדכני אותו בכל הוספה או הסרה של סימון. הציגי גם כמה מוקשים נותרו לסימון: מספר המוקשים הכולל פחות מספר הדגלים שהוצבו. המונה מבוסס על הסימונים של המשתמשת ואינו בודק אם הדגלים הוצבו במקומות הנכונים.

## חלק ד ניצחון וסיום משחק

הציגי הודעת ניצחון כאשר כל המשבצות הבטוחות נפתחו וכל המוקשים מסומנים בדגלים. במצב הזה המשבצות היחידות שנותרו סגורות הן משבצות המוקשים, וכולן מסומנות.

סימון כל המשבצות הסגורות בדגלים אינו מספיק בפני עצמו: דגל על משבצת בטוחה אינו יכול להיחשב לזיהוי מוקש, ואין להכריז על ניצחון כשמשבצות בטוחות נשארו סגורות.

לאחר ניצחון או הפסד:

1. עצרי את הטיימר.
2. השאירי את הודעת הסיום גלויה.
3. אל תאפשרי להמשיך לפתוח משבצות או לשנות דגלים באותו משחק.
4. אפשרי להתחיל משחק חדש באמצעות כפתור האיפוס.

## חלק ה איפוס וטיימר

הוסיפי לממשק כפתור איפוס, מוני מוקשים ודגלים וטיימר שמציג את משך המשחק בשניות. הציגי גם את מספר המוקשים הכולל במשחק הנוכחי.

- הטיימר מתחיל בלחיצה הראשונה על משבצת בלוח, בין שזו פתיחה ובין שזה סימון בדגל.
- הטיימר פועל פעם אחת לכל משחק. לחיצות נוספות לא יוצרות טיימרים נוספים.
- הטיימר נעצר בניצחון או בהפסד.
- לחיצה על איפוס יוצרת לוח חדש עם פיזור מוקשים אקראי לפי ההגדרות הנוכחיות.
- איפוס מסיר את כל הדגלים, סוגר את כל המשבצות, מנקה את הודעת הסיום ומחזיר את המונים למצב ההתחלתי.
- לאחר איפוס הטיימר מציג 0 ואינו מתחיל לפעול עד ללחיצה הראשונה על הלוח החדש.

## חלק ו הגדרות דינמיות

אפשרי למשתמשת לקבוע את גודל הלוח ואת מספר המוקשים לפני יצירת משחק חדש. הלוח יישאר ריבועי: גודל 9 פירושו 9 שורות ו־9 עמודות.

ברירת המחדל תהיה 9 על 9 עם 10 מוקשים. שינוי ההגדרות והתחלת משחק חדש צריכים להתאים גם את הלוח וגם את המונים, ולא רק את התצוגה.

בדקי את הקלט לפני יצירת הלוח:

- גודל הלוח חייב להיות מספר שלם של 2 ומעלה.
- מספר המוקשים חייב להיות מספר שלם של 1 ומעלה וקטן ממספר המשבצות.
- במקרה של קלט לא תקין, הציגי הודעה ברורה ואל תיצרי לוח לפי הקלט השגוי.

אין להניח בחישובים שהלוח תמיד בגודל 9 או שיש בו תמיד 10 מוקשים.

## דרישות כתיבת הקוד והממשק

### TypeScript

- כל קוד הלוגיקה והעבודה עם ה־DOM ייכתב בקובצי TypeScript.
- הגדירי טיפוסים מפורשים למשתנים, לפרמטרים ולערכי החזרה של פונקציות. הגדירי גם את טיפוסי השדות במבני הנתונים.
- אין להשתמש ב־`any`, במפורש או במשתמע. הדרישה לטיפוסים מפורשים בתרגיל מחמירה יותר מבדיקת `noImplicitAny` בלבד.
- אל תבטלי את בדיקות הטיפוסים כדי להסתיר שגיאות.

### מבנה וקריאות

- חלקי את הקוד לפונקציות בעלות אחריות ברורה ותני להן שמות שמתארים את פעולתן.
- הפרידי בין לוגיקת המשחק לבין הקוד שמציג את הלוח ומטפל באירועי הממשק.
- לוגיקת המשחק לא אמורה להסתמך על טקסט, צבע או מחלקת CSS כדי לדעת מה מצב המשבצת.
- שמרי על מבנה תיקיות מסודר וחלוקה לקבצים. אפשר להוסיף תיקיות תחת `src` לפי הצורך.
- הימנעי משכפול לוגיקה ומערכים קבועים שלא מתאימים לשינוי גודל הלוח.

### תצוגה ואירועים

- צרי עיצוב קריא עם הבדל ברור בין משבצת סגורה, משבצת פתוחה, דגל ומוקש.
- הלוח יהיה רספונסיבי: גודל המשבצות יותאם לשטח הזמין ולגודל הלוח, כך שגם בחלון צר יהיה אפשר להשתמש במשחק.
- השתמשי באירועים המתאימים לפעולות המשתמשת. ודאי שלא מצטברים מאזינים כפולים לאחר איפוס.
- הציגי בממשק הסבר קצר על לחיצה שמאלית ועל לחיצה ימנית.

## בונוס פתיחת שכנות בלחיצה כפולה

ממשי פתיחת שכנות באמצעות לחיצה כפולה על משבצת מספר שכבר נפתחה. אם תרצי, אפשר לתמוך גם בלחיצה על שני כפתורי העכבר יחד.

1. ספרי את הדגלים במשבצות השכנות למשבצת שעליה הופעלה הפעולה.
2. אם מספר הדגלים קטן מהמספר שבמשבצת, אל תפתחי משבצות נוספות.
3. אם מספר הדגלים גדול או שווה למספר שבמשבצת, פתחי את כל השכנות הסגורות שאינן מסומנות בדגל.
4. אם אחת המשבצות שנפתחות מכילה מוקש, המשחק מסתיים בהפסד. סימון שגוי בדגלים אינו מגן מפני הפסד.
5. אם נפתחת משבצת שמספרה 0, הפעילי עליה את הפתיחה הרקורסיבית הרגילה.

תנאי ההפעלה בבונוס הוא גדול או שווה, בהתאם לאפיון התרגיל. אין לשנות אותו לבדיקה של שוויון בלבד.

## בדיקה לפני ההגשה

בדיקת הבנייה אינה בודקת את כללי המשחק. בדקי בעצמך גם את התרחישים הבאים:

- [ ] לוח ברירת המחדל מכיל 81 משבצות ו־10 מוקשים במיקומים שונים.
- [ ] בפתיחת המשחק לא ניתן לראות את המוקשים.
- [ ] המספרים נכונים גם באמצע הלוח וגם בקצוות ובפינות.
- [ ] לחיצה על משבצת ללא מוקשים סביבה פותחת את האזור הריק ואת גבול המספרים שלו.
- [ ] הפתיחה הרקורסיבית אינה פותחת דגלים או מוקשים ואינה נתקעת בלולאה.
- [ ] לחיצה ימנית מוסיפה ומסירה דגל ומעדכנת את מונה הדגלים ואת מונה המוקשים שנותרו לסימון.
- [ ] משבצת מסומנת אינה נפתחת בלחיצה שמאלית ומשבצת פתוחה אינה מקבלת דגל.
- [ ] הטיימר מתחיל בפעולה הראשונה בלבד ונעצר בסיום המשחק.
- [ ] לחיצה על מוקש חושפת את המוקשים ומציגה הפסד.
- [ ] הודעת ניצחון מופיעה רק כשכל המשבצות הבטוחות פתוחות וכל המוקשים מסומנים.
- [ ] לא ניתן להמשיך לשחק לאחר ניצחון או הפסד.
- [ ] איפוס באמצע משחק ואיפוס לאחר סיום מחזירים את הלוח והמונים למצב ההתחלתי.
- [ ] שינוי גודל הלוח ומספר המוקשים משפיע על המשחק בפועל.
- [ ] קלט חסר, מספרים שאינם שלמים ומספר מוקשים שאינו מתאים לגודל הלוח מטופלים בצורה ברורה.
- [ ] הממשק נשאר שימושי גם כאשר משנים את גודל החלון.
- [ ] אם מימשת את הבונוס, בדקת גם מקרה שבו דגל הוצב במקום שגוי ופתיחת השכנות גורמת להפסד.

אפשר להשתמש בדיבאגר ובבדיקות זמניות כדי לבדוק מספרים, תנאי ניצחון ומצבי קצה. הסירי מההגשה מידע שמגלה לשחקנית היכן נמצאים המוקשים.
